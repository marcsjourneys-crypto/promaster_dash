# Local iOS Builds (EAS-free)

ProMaster Dash builds entirely on the MacBook now — no EAS, no per-build cost.
This is a CNG/prebuild project: the `ios/` folder is generated by `expo prebuild`
and is **gitignored**. Never commit it, never hand-edit it. All native config
(permissions, background modes, capabilities, build number) is driven by
`app.json` + config plugins; prebuild regenerates the native project from those.

**Machine roles:**
- **Windows** — daily coding + Metro dev server.
- **MacBook** — native builds (dev client + App Store archives).

---

## (a) Dev-client rebuild — Mac, only when native code changes

Needed when you add/upgrade a native module or change a config plugin
(e.g. adding MapLibre, BLE, a new Expo package). Pure JS/TS changes do **not**
need this — see (b).

```sh
git pull
cd mobile
npm install
npm run prebuild:clean      # regenerates ios/ with current native deps
npm run ios:device          # installs Debug dev client to the connected iPhone
```

iPhone must be connected by cable, unlocked, with Developer Mode on.

## (b) Daily JS/TS dev — Windows, no Mac needed

The installed dev client loads JS from any Metro server on the network.

```powershell
cd mobile
npm start
```

On the iPhone, open the ProMaster Dash dev client and connect to
`http://<windows-LAN-ip>:8081` (or pick the server from the list).

Requirements:
- Phone and PC on the **same Wi-Fi / subnet** (no AP/client isolation).
- Windows Defender Firewall: allow **inbound TCP 8081** for Node on the
  **Private** profile (one-time rule).

## (c) Production release — Mac

```sh
# 1. On Windows: bump version/build in app.json, commit, push
#    - ios.buildNumber MUST increase every upload (autoIncrement is gone).
#    - version = marketing version (e.g. 1.0.1); bump when user-facing.

# 2. On Mac:
git pull
cd mobile
npm install
npm run prebuild:clean
open ios/*.xcworkspace
```

In Xcode: select **Any iOS Device (arm64)** → Product → **Archive** →
Organizer → **Distribute App** → **App Store Connect** → **Upload**.
Signing is automatic (Apple Distribution cert). Fallback uploader: export
the `.ipa` and use the **Transporter** app.

**Build-number discipline:** App Store Connect rejects a duplicate build
number *at upload time*. If that happens, bump `ios.buildNumber`, re-run
prebuild:clean, re-archive. Non-destructive. The last EAS cloud build was
build **3**; local numbering continues from **4**.

## (d) Switching branches with different native deps

If two branches differ in native modules (e.g. `main` vs a branch that adds
a native package), run `npm run prebuild:clean` after switching before you
build. `prebuild:clean` deletes and regenerates `ios/` so stale native state
from the other branch can't leak in.

---

## Notes

- **EAS is dormant, not deleted.** `extra.eas.projectId` stays in `app.json`,
  so a one-off cloud build (`eas build ...`) is still possible if the Mac is
  ever unavailable. Nothing is billed while it sits unused.
- **Do not revoke the EAS distribution certificate.** Apple allows two iOS
  distribution certs; EAS holds one and Xcode mints its own. They coexist.
